# ระบบงานเบิกของและ Skill Matrix

**เว็บใช้งาน:** https://nk02388-cyber.github.io/Withdrawal-Skill-Matrix/

**GitHub:** https://github.com/nk02388-cyber/Withdrawal-Skill-Matrix

เปิดเว็บแล้วดู Dashboard, ใบเบิก และ Skill Matrix ได้ทันทีโดยไม่ต้อง Login ข้อมูลอยู่ใน Supabase กลางและโหลดใหม่ทุก 15 วินาทีเมื่อหน้าเว็บเปิดอยู่ จึงใช้งานหลายเครื่องได้

## เพิ่มและแก้ข้อมูล

กด **เข้าสู่โหมดทำงาน** ที่มุมขวาบน แล้วเลือกสิทธิ์และกรอกชื่อผู้ใช้กับรหัสผ่าน ระบบแยกสิทธิ์ที่ฐานข้อมูล:

- **หัวหน้า**: เพิ่มหรือปิดพนักงานและ Job, ประเมินทักษะ, สร้างและแก้ใบเบิก, ยกเลิกใบเบิกที่ยังเปิดอยู่
- **ผู้ปฏิบัติงาน**: เริ่มงาน, พักงาน, กลับมาทำงานต่อ, จบงาน หรือปิดเป็นเบิกไม่ครบ

Dashboard, ใบเบิก, ตัวกรอง และรายงานยังดูได้โดยไม่ต้องเข้าสู่โหมดทำงาน กด **ออกจากโหมด** เพื่อลบรหัสออกจากแท็บ รหัสจะคงอยู่เฉพาะในแท็บนั้นระหว่างใช้งาน

1. เพิ่มพนักงานในหน้า **พนักงาน**
2. เพิ่ม Job ในหน้า **ประเภทงานและทักษะ** แล้วกำหนดระดับ 0–4
3. สร้างใบเบิก ระบุเลขที่ใบเบิก, Job, ผู้รับผิดชอบ แล้วเลือก **ใช้ BOM** หรือ **เบิกเฉพาะรายการจาก Stock** ในโหมด BOM ค้นหาสินค้า FG ด้วยรหัส ชื่อ หรือหลาย Keyword เลือกสูตรและจำนวนที่ต้องการผลิต ระบบคำนวณรายการวัสดุตามสูตรให้ตรวจสอบ
4. รายการที่ไม่มีใน BOM ให้ค้นด้วยรหัส PK, ชื่อสินค้า, คำบางส่วน หรือหลาย Keyword ในช่อง **รายการนอก BOM** เลือกผลค้นหาจาก Stock ล่าสุด ใส่จำนวนเบิก แล้วกด **เพิ่มรายการ** เพิ่มได้ทั้งในใบเบิก BOM และใบเบิกที่ใช้ Stock อย่างเดียว ระบบบันทึกด้วยรหัส PK ของรายการที่เลือก
5. ผู้ปฏิบัติงานกด **เริ่มงาน** แล้วเลือก **พักงาน**, **ทำงานต่อ**, **จบงาน** หรือ **เบิกไม่ครบ** เวลามาจากฐานข้อมูลกลาง เบิกไม่ครบเป็นสถานะปิดงาน
6. หัวหน้ากด **แก้ไข** เพื่อเปลี่ยนเลขที่ใบเบิก, Job, ผู้รับผิดชอบ, จำนวน FG, เวลาเริ่ม–สิ้นสุด หรือหมายเหตุ โดยต้องใส่เหตุผล เวลาในฟอร์มเป็นเวลาไทย งานรอดำเนินการไม่มีเวลาให้แก้ งานกำลังทำ/พักแก้เวลาเริ่มได้ งานจบ/เบิกไม่ครบแก้ได้ทั้งสองเวลา งานยกเลิกแก้เวลาสิ้นสุดได้และแก้เวลาเริ่มได้เฉพาะใบที่เคยเริ่มงาน ระบบไม่รับเวลาอนาคตหรือเวลาสิ้นสุดก่อนเวลาเริ่ม จำนวนวัสดุตาม BOM จะคำนวณใหม่ ส่วนจำนวนรายการนอก BOM ที่เลือกไว้จะคงเดิม หัวหน้ากด **ยกเลิก** ได้เฉพาะใบเบิกที่ยังเปิดอยู่

การพักงาน เบิกไม่ครบ ยกเลิก และแก้ไข ต้องใส่เหตุผล กด **ประวัติ** ในใบเบิกเพื่อดูเวลา ผู้ใช้บทบาท เหตุผล และค่าก่อน–หลังของการแก้ไข รายการเก่าก่อนเปิดประวัติจะระบุว่าเป็นข้อมูลนำเข้า

ในหน้า **งานเบิกของ** ค้นหาเลขที่ใบเบิกและกรองตามพนักงาน, Job, วันที่สร้างใบเบิก และทุกสถานะได้ ช่วงวันที่ใช้วันตามเวลาไทย (UTC+7) และรวมทั้งวันแรกกับวันสุดท้าย ปุ่ม **พิมพ์รายงาน / PDF** พิมพ์เฉพาะรายการที่ตรงกับตัวกรอง รวมข้อมูล FG, จำนวน, เวลาเริ่ม–สิ้นสุด, เหตุผลสถานะ และวัสดุตาม BOM สามารถเลือก “Save as PDF” ในหน้าต่างพิมพ์ของเบราว์เซอร์

Dashboard แสดงภาพพนักงาน จิรถิตติ์, ภูรินทร์ และโซม่อน พร้อมประสิทธิภาพรายคนจากใบเบิกจริง: งานจบ, เบิกไม่ครบ, งานที่ยังเปิด, อัตราจบงาน และเวลามัธยฐานจากเวลาเริ่มถึงจบ (รวมเวลาพัก) อัตราจบงานหารเฉพาะงานจบกับเบิกไม่ครบ จึงไม่รวมงานที่ยังเปิดหรือถูกยกเลิก และแสดง `—` เมื่อยังไม่มีงานปิด

Skill Matrix คำนวณระดับอัตโนมัติแยกตาม Job จากจำนวนงานจบ: 0 = ยังไม่มี, 1 = 1–2, 2 = 3–5, 3 = 6–11, 4 = 12 งานขึ้นไป ระดับนี้เป็นตัวชี้วัดประสบการณ์จากประวัติงาน ไม่ใช่การรับรองความชำนาญหรือคุณภาพงาน ระดับที่หัวหน้าประเมิน 0–4 ยังคงแสดงแยกและแก้ได้ในหน้า **ประเภทงานและทักษะ**

## สูตรการผลิตจาก PK WMS

`pk-bom.json` ดึงเฉพาะรหัส FG, ชื่อ FG, รหัส/ชื่อ/หน่วยวัสดุ และอัตราใช้ต่อ 1 FG จาก `PK-WMS/index.html` ไม่ดึงยอดสต็อกหรือมูลค่าวัสดุ หน้าเว็บโหลดไฟล์ล่าสุดจาก GitHub ก่อน และใช้ไฟล์ที่ deploy อยู่เป็นสำรอง สูตรจะปรับจาก PK WMS วันละครั้งผ่าน GitHub Actions และกดรันเองได้ที่ workflow **Sync PK WMS BOM**

จำนวนวัสดุที่แสดงคือ **อัตรา BOM × จำนวน FG** ปัดเป็น 4 ตำแหน่ง ยังไม่ใช่การตัดสต็อกหรือการยืนยันว่าของมีพอ สูตรที่อัตราใช้ไม่ครบจะไม่ให้สร้างใบเบิก เมื่อบันทึกแล้ว ระบบเก็บรายการวัสดุและเวอร์ชันสูตรไว้ในใบเบิกนั้น เพื่อรักษาประวัติแม้ PK WMS แก้สูตรภายหลัง

รายการนอก BOM โหลดรหัส ชื่อ และหน่วยจากสแนปช็อต Stock ล่าสุดในฐานข้อมูล PK WMS ทุกครั้งที่เปิดฟอร์มและตรวจซ้ำก่อนบันทึก แสดงวันที่ของสแนปช็อต และเก็บรหัสสแนปช็อตกับแต่ละรายการในใบเบิก ไม่ดึงยอดคงเหลือหรือมูลค่าสต็อกมาแสดง และยังไม่หักยอด Stock ใน PK WMS หากโหลด Stock ล่าสุดไม่ได้ จะไม่ให้เพิ่มรายการนอก BOM

การรีเฟรชด้วยตนเอง: ดาวน์โหลด `index.html` ล่าสุดจาก repo `nk02388-cyber/PK-WMS` แล้วรัน `node scripts/sync-pk-bom.cjs <path-to-PK-WMS-index.html>` จากนั้น commit `pk-bom.json`

## ขอบเขตการเข้าถึง

ทุกคนที่มีลิงก์ดูข้อมูลทั้งหมดรวมถึงเหตุผลและประวัติได้ ผู้ที่รู้รหัสของบทบาทนั้นทำรายการตามสิทธิ์ได้ ประวัติบันทึกชื่อผู้ใช้ร่วมของบทบาท เช่น Admin หรือ pkbcl01 จึงไม่ระบุตัวบุคคลที่กดแก้หรือกดเวลา และไม่เหมาะใช้เป็นหลักฐานเวลาทำงานที่ต้องตรวจสอบผู้กระทำเป็นรายคน อย่าใส่ข้อมูลลับหรือข้อมูลส่วนบุคคลที่ไม่ต้องการให้คนที่มีลิงก์เห็นในใบเบิก

รหัสของทั้งสองบทบาทถูกเก็บเป็น hash ใน Supabase และไม่ได้อยู่ใน GitHub `config.js` มีเฉพาะ publishable key ที่เปิดเผยได้ ฟังก์ชันฐานข้อมูลตรวจชื่อผู้ใช้ รหัส และสิทธิ์ทุกครั้ง การอ่านใช้ฟังก์ชันที่คืนเฉพาะข้อมูลสำหรับ Dashboard โดยไม่เปิดตารางบัญชีเดิมหรืออีเมล

## สำหรับดูแลระบบ

- `schema.sql` เป็นโครงสร้างเดิมของโครงการ
- `no-login-migration.sql` เพิ่มโหมดดูข้อมูลสาธารณะและรหัสร่วม รันต่อจาก `schema.sql` ในโครงการใหม่
- `bom-migration.sql` เพิ่มข้อมูล FG, จำนวน, รายการวัสดุ และฟังก์ชันบันทึกใบเบิกแบบ BOM รันต่อจาก `no-login-migration.sql`
- `role-codes-migration.sql` แยกรหัสหัวหน้า/ผู้ปฏิบัติงาน พร้อมปิด RPC รุ่นรหัสร่วมเดิม รันต่อจาก `bom-migration.sql`
- การย้ายระบบเดิมใช้ `activate_role_codes` ครั้งเดียวด้วยรหัสร่วมเดิม เพื่อเก็บ hash ของรหัสทั้งสองและลบรหัสร่วมเดิม
- `role-codes-finalize.sql` ปิดสิทธิ์เรียกฟังก์ชันตั้งค่ารหัสหลังเปิดใช้ทั้งสองบทบาทแล้ว
- `ticket-events-migration.sql` เพิ่มสถานะ เหตุผล ประวัติ และ RPC ตามสิทธิ์ รันหลัง `role-codes-finalize.sql`
- `stock-withdrawal-migration.sql` เพิ่มใบเบิกที่มีรายการนอก BOM และรักษารายการเหล่านั้นเมื่อแก้จำนวน FG รันหลัง `ticket-events-migration.sql`
- `supervisor-time-edit-migration.sql` เพิ่ม RPC ให้หัวหน้าแก้เวลาและข้อมูลใบเบิกในครั้งเดียว พร้อมตรวจสถานะและบันทึกประวัติ รันหลัง `stock-withdrawal-migration.sql`
- PK WMS ใช้ `supabase-withdrawal-stock-catalog.sql` เพื่อเปิดเฉพาะแคตตาล็อกรหัส ชื่อ หน่วย และวันที่สแนปช็อตให้เว็บใบเบิก
- `app.js` ใช้ Supabase RPC ไม่มีรหัสผ่านฝังในไฟล์
- ไฟล์เว็บถูกโฮสต์จาก root ของ branch `main` บน GitHub Pages
